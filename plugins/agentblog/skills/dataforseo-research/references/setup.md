## 1. The two access paths, and which to prefer

DataForSEO is one HTTP API. There are two ways to reach it, and they cost the
same because the MCP server is a pass-through to the same account.

|                    | MCP server                                | REST with curl               |
| ------------------ | ----------------------------------------- | ---------------------------- |
| Setup              | One config file, then restart the session | None beyond credentials      |
| Discovery          | Tools appear with typed parameters        | You supply the path and body |
| Response size      | Trimmed by default, see section 4         | Trimmed only if you ask      |
| Endpoint coverage  | 90 tools, some on stale paths             | Every documented endpoint    |
| Failure visibility | Errors arrive as text, not tool failures  | Status code is in the body   |

**Prefer MCP when it is already configured. Prefer REST when it is not.**
Configuring an MCP server requires a session restart to take effect, so a skill
that stops to install one has ended the run. REST works in the same turn.

Never set up the MCP server without asking. It writes to the user's Claude Code
configuration, which is theirs.

## 2. Getting credentials

Registration is at https://app.dataforseo.com/register and the credentials are on
the API Access tab at https://app.dataforseo.com/api-access.

**The API password is generated by DataForSEO and is not the account password.**
A user who types their login password into the config gets a server that connects
and then returns 401 on every call, which is the most common setup failure.

New accounts carry $1 of credit, which is real money and enough for a first
baseline run if you spend it deliberately. The minimum top-up after that is $50.
Email or phone verification has to be completed first, or every call returns
status `40104`.

Do not create a second account to get another $1. DataForSEO treats it as a terms
violation and suspends both, reported as status `40201`.

## 3. Where the credentials live, and the trap

These are secrets. The rule is the one AgentBlog already applies to
`INDEXNOW_KEY` and `AGENTBLOG_REVALIDATE_SECRET`: they belong in a file git does
not track.

**The trap.** Claude Code expands `${VAR}` in `.mcp.json` from the shell
environment of the process that launched it. It does not read `.env.local`, and
AgentBlog puts secrets in `.env.local`. So the natural move, putting the
credentials where every other AgentBlog secret lives and referencing them from
`.mcp.json`, produces a server that reports itself connected and fails
every call with a 401.

The MCP server never validates credentials at startup. It builds a syntactically
valid Basic header out of two empty strings, so the process starts cleanly and
`claude mcp list` says the server is connected. Connected does not mean
authenticated, and nothing tells you which one you have until a call fails.

Two arrangements work. Say which one you are using rather than assuming.

- **Shell export**, for the MCP path. The user exports both variables in the
  shell profile, then starts Claude Code from that shell. `.mcp.json` refers to
  them as `${DATAFORSEO_USERNAME}` and `${DATAFORSEO_PASSWORD}`, so the file
  itself holds no secret and is safe to commit.
- **`.env.local`**, for the REST path. `curl` reads it because you source it in
  the same command. This is the arrangement that matches the rest of AgentBlog,
  and it is the reason the REST path is worth keeping even after MCP works.

Check `git check-ignore .env.local` before writing anything into it. If git
tracks it, stop and say so. A committed API password is a bill somebody else can
run up.

## 4. Path A: the MCP server

The package is `dataforseo-mcp-server` on npm. It requires **Node 20 or newer**,
which contradicts both its own README and the DataForSEO landing page. On Node 18
it installs and then fails at runtime.

Project scope, credentials by reference, pinned version:

```json
{
  "mcpServers": {
    "dataforseo": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dataforseo-mcp-server@2.9.11"],
      "env": {
        "DATAFORSEO_USERNAME": "${DATAFORSEO_USERNAME}",
        "DATAFORSEO_PASSWORD": "${DATAFORSEO_PASSWORD}",
        "ENABLED_MODULES": "DATAFORSEO_LABS,SERP,AI_OPTIMIZATION,ONPAGE"
      }
    }
  }
}
```

Four things in that block are load-bearing.

- **`ENABLED_MODULES` is not optional in practice.** Left unset it loads all ten
  modules and 90 tools into the session. The four above are what this skill uses.
  The full set is `AI_OPTIMIZATION`, `SERP`, `KEYWORDS_DATA`, `ONPAGE`,
  `DATAFORSEO_LABS`, `BACKLINKS`, `BUSINESS_DATA`, `DOMAIN_ANALYTICS`,
  `CONTENT_ANALYSIS`, `MERCHANT`. A name outside that list is fatal rather than
  ignored: the server throws at startup and presents as a failed connection with
  no useful message.
- **The version is pinned.** `npx -y dataforseo-mcp-server` floats to whatever is
  latest at launch, so the tool surface can change between sessions.
- **The credentials are references.** See section 3.
- **`type` is `stdio`.** The hosted server at `https://mcp.dataforseo.com/mcp` is
  the alternative, taking `Authorization: Basic` as a header. Both `/mcp` and
  `/http` are served, and DataForSEO's own pages disagree about which to use.

Do not tell a user to run `claude test-mcp`. DataForSEO's help centre recommends
it and the command does not exist. `claude mcp list` is the real one.

**Response trimming.** The server appends `.ai` to every endpoint path unless
`DATAFORSEO_FULL_RESPONSE=true`. That is a DataForSEO server-side feature: it
strips empty fields, drops `position` and `xpath`, rounds floats, and **defaults
`depth` and `limit` to 10**. It costs the same as the untrimmed response. Leave
it on. If a field you need is missing, that is the first thing to suspect.

**Five LLM Mentions tools are on stale paths.** At 2.9.11 the server calls
`/llm_mentions/search/live`, `/aggregated_metrics/live`,
`/cross_aggregated_metrics/live`, `/top_domains/live`, and `/top_pages/live`. The
documented paths are `/search_mentions/live`, `/target_metrics/live`,
`/multi_target_metrics/live`, `/top_mentioned_domains/live`, and
`/top_mentioned_pages/live`. Whether DataForSEO still aliases the old names could
not be established from outside. If those tools return a not-found error, use
REST with the documented paths in `references/endpoints.md`.

## 5. Path B: REST with curl

Basic auth is the only mechanism. There is no token exchange and no API key
header.

```bash
set -a; [ -f .env.local ] && . ./.env.local; set +a

curl -s -X POST "https://api.dataforseo.com/v3/dataforseo_labs/google/bulk_keyword_difficulty/live" \
  -u "$DATAFORSEO_USERNAME:$DATAFORSEO_PASSWORD" \
  -H 'Content-Type: application/json' \
  -d '[{"keywords":["headless cms"],"location_code":2840,"language_code":"en"}]'
```

Three shapes to get right, each of which fails loudly the first time and quietly
later:

- **The body is always an array**, even for one task. A bare object returns
  `40503`.
- **Live endpoints take exactly one task per call** and return `40000` for more.
  Task-based endpoints take up to 100 and return `40006` past that.
- **Unknown fields are rejected**, not ignored, with `40506`. Do not send extra
  keys defensively.

Append `.ai` to the path to get the same trimmed response the MCP server gets, at
the same price.

## 6. Verifying without spending anything

Two free instruments, and both should run before the first billable call.

**The account probe.** `GET /v3/appendix/user_data` is free and returns the
account's live balance, its rate limits, and its actual price list per endpoint.

```bash
curl -s -u "$DATAFORSEO_USERNAME:$DATAFORSEO_PASSWORD" \
  "https://api.dataforseo.com/v3/appendix/user_data"
```

Read three things out of it: `money.balance`, so you know whether the run can
finish; the `price` map, so cost estimates use the account's real prices rather
than the published ones; and `llm_mentions_subscription_expiry_date`, which tells
you whether the AI citation half of this skill is available at all.

**The sandbox.** Swapping the host to `https://sandbox.dataforseo.com` runs any
call for free against dummy data with the identical response shape. Use it to
check that a request body is well formed before paying for the real one. The MCP
server cannot reach it, because the base URL is hardcoded with no override, so
sandbox verification is a REST-only move.

## 7. Reading a failure

DataForSEO puts `status_code` at two levels, and **the top-level one being
`20000` does not mean the task succeeded**. Check `tasks_error`, then each
`tasks[i].status_code`.

Through the MCP server this gets worse: a failed call is returned as a text block
beginning `Error:` rather than as a tool failure, so an agent that only checks
whether the tool call threw will read the error as data and report a finding
based on nothing.

| Code                      | Meaning                           | Action                                         |
| ------------------------- | --------------------------------- | ---------------------------------------------- |
| `20000`                   | Success                           | Continue                                       |
| `40100`                   | Not authorised                    | Credentials wrong or unexpanded. Section 3     |
| `40104`                   | Account not verified              | User completes email or phone verification     |
| `40102`                   | No search results                 | Not an error. The query has no data            |
| `40200`, `40210`          | Balance empty, insufficient funds | Stop. Do not retry                             |
| `40203`                   | Cost limit hit                    | Stop. The user set this in the dashboard       |
| `40204`                   | Not entitled                      | Subscription required. Record it, do not retry |
| `40202`                   | Over 2,000 calls per minute       | Back off                                       |
| `40209`                   | Over 30 concurrent requests       | Back off. This one fires first                 |
| `40501`, `40503`, `40506` | Bad request body                  | Your bug. Fix it, do not retry                 |
| `40505`                   | Stale location code               | Refetch the location list for that API         |
| `50401`                   | Live task passed 120 seconds      | Retry once, then narrow the request            |

Retry `40103`, `50000`, `50301`, `50303`, `50401`, `50402`. Never retry a `405xx`
or a funds error: the first is your request and the second needs a human.

## 8. Degraded modes, and what to do in each

Each of these is a state where part of this skill works and part does not. Name
the state in the report. **Do not silently fall back to a smaller run and present
it as a complete one.**

| State                        | Detection                                     | What still works                                                            |
| ---------------------------- | --------------------------------------------- | --------------------------------------------------------------------------- |
| No credentials anywhere      | The SKILL.md step 2 ladder reaches nothing    | Nothing. Stop and give the user section 2                                   |
| Credentials, no MCP server   | Env vars set, no matching tools               | All of it, over REST                                                        |
| MCP connected but 401        | Tools exist, every call returns 401           | Switch to REST and tell the user their expansion is broken                  |
| No LLM Mentions subscription | `40204`, or the expiry date is absent or past | Everything except AI citation measurement. Say which sections are missing   |
| Balance too low for the plan | `money.balance` below the estimate            | Narrow to the highest-value calls, get the user to approve the shorter plan |
| Balance empty                | `40200` or `40210`                            | Nothing billable. The free probes still answer                              |

When a state removes a section, the run report says which section is missing and
why. A research report that quietly omits the AI citation half reads exactly like
one where the site has no AI citations.
